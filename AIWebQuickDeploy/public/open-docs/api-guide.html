📖 概述

重要提示： 本文档提供完整的对话系统开放 API 接入流程，所有接口无需用户认证，不检查额度，不扣费。

基础地址： http://your-domain:9520/api/open

认证方式： 无需认证，通过 userId 参数区分不同用户

💡 核心概念

1. 用户标识 (userId)

  • 任意数字即可，用于区分不同用户的会话
  • 不需要在系统中真实存在
  • 建议使用您系统中的用户 ID

2. 对话组 (ChatGroup)

  • 每个对话需要属于一个对话组
  • 对话组可以绑定角色 (App)
  • 对话组包含模型配置和上下文

3. 上下文管理（重要）

✨ 核心特性：
  • 只需使用 options.groupId 即可自动保持对话上下文
  • 系统会自动查询该对话组的历史记录
  • 不需要手动管理 parentMessageId
  • 返回的 chatId 是当前对话记录ID

🔄 完整对话流程

1. 创建对话组（获得 groupId）
↓
2. 发起对话（带 groupId）
↓
3. 系统自动查询历史对话，构建上下文
↓
4. 继续对话（带相同的 groupId）
↓
5. 系统自动加载上下文
↓
6. 查询对话历史（可选）
⚡ 关键优势： 只需传递 groupId，系统自动管理所有上下文，默认加载最近 12 轮对话。

📡 接口详细说明

1️⃣ 创建对话组

接口： POST /open/group/create

用途： 创建一个新的对话组，可选绑定角色

请求参数

参数 类型 必填 说明
userId number 必填 外部用户ID
appId number 可选 角色ID（不传则创建默认对话）
modelConfig object 可选 模型配置（不传则使用系统默认）
示例 1：创建默认对话组
curl -X POST http://localhost:9520/api/open/group/create \
  -H "Content-Type: application/json" \
  -d '{
    "userId": 1001
  }'
响应
{
  "success": true,
  "data": {
    "id": 456,
    "userId": 1001,
    "appId": null,
    "title": "新对话",
    "isSticky": false,
    "isDelete": false,
    "createdAt": "2025-10-22T08:30:20.000Z"
  }
}

2️⃣ 发起对话

接口： POST /open/chat/chat-process

用途： 发起对话，支持流式返回

请求参数

参数 类型 必填 说明
userId number 必填 外部用户ID
prompt string 必填 用户提问内容
options.groupId number 推荐 对话组ID（用于自动管理上下文）
appId number 可选 角色ID
model string 可选 模型标识（如 gpt-3.5-turbo）
示例：首次对话
curl -X POST http://localhost:9520/api/open/chat/chat-process \
  -H "Content-Type: application/json" \
  -d '{
    "userId": 1001,
    "prompt": "你好，请介绍一下你自己",
    "options": {
      "groupId": 456
    }
  }'
响应（流式）
data: 你好
data: ！我是
data: 一个AI
data: 助手

{"text":"你好！我是一个AI助手...","chatId":789,"userBalance":null}
✨ 继续对话： 只需继续传递相同的 groupId，系统会自动加载之前的对话上下文，无需手动管理消息ID！

3️⃣ 查询对话组列表

接口： POST /open/group/query

请求示例
curl -X POST http://localhost:9520/api/open/group/query \
  -H "Content-Type: application/json" \

接口： POST /open/chatLog/query

请求参数

参数 类型 必填 说明

请求示例
curl -X POST http://localhost:9520/api/open/group/del \

Node.js 完整客户端

const axios = require('axios');

const API_BASE = 'http://localhost:9520/api/open';

class ChatClient {
  constructor(userId) {
    this.userId = userId;
    this.groupId = null;
  }

  // 创建对话组
  async createGroup(appId = null) {
    const response = await axios.post(`${API_BASE}/group/create`, {
      userId: this.userId,
      appId
    });
    this.groupId = response.data.data.id;
    return response.data;
  }

  // 发起对话（自动带上下文）
  async chat(prompt) {
    const response = await axios.post(`${API_BASE}/chat/chat-process`, {
      userId: this.userId,
      prompt,
      options: { groupId: this.groupId }
    }, {
      responseType: 'stream'
    });

    let fullText = '';
    let chatId = null;

    return new Promise((resolve, reject) => {
      response.data.on('data', (chunk) => {
        const lines = chunk.toString().split('\n');
        for (const line of lines) {
          if (line.startsWith('data: ')) {
            const text = line.slice(6);
            fullText += text;
            process.stdout.write(text);
          } else if (line.trim() && line.startsWith('{')) {
            try {
              const result = JSON.parse(line);
              chatId = result.chatId;
              console.log('\n');
              resolve({ text: fullText, chatId });
            } catch (e) {}
          }
        }
      });
      response.data.on('error', reject);
    });
  }
}

// 使用示例
async function main() {
  const client = new ChatClient(1001);

  await client.createGroup();
  await client.chat('什么是人工智能？');
  await client.chat('它有哪些应用？'); // 自动带上下文
}

main().catch(console.error);

2. 对话组管理

  • 为每个独立的对话主题创建新的对话组
  • 定期清理不需要的对话组
  • 同一个对话组内会自动保持上下文（最近12轮）

3. 错误处理

async function chatWithRetry(params, maxRetries = 3) {
  for (let i = 0; i < maxRetries; i++) {
    try {
      return await chat(params);
    } catch (error) {
      if (i === maxRetries - 1) throw error;
      await sleep(1000 * (i + 1)); // 指数退避
    }
  }
}

❓ 常见问题

Q1: 如何保持对话上下文？

A: 只需要在每次对话时传递相同的 groupId，系统会自动查询该对话组的历史记录（默认最近12轮），无需手动管理任何消息ID。

Q2: chatId 有什么用？

A: chatId 是当前对话记录的ID，可用于：
  • 查询对话历史
  • TTS 语音合成
  • 删除特定对话
注意：chatId 不用于上下文传递，上下文由 groupId 自动管理。

Q3: 外部接口会扣费吗？

A: 所有 /api/open/* 接口都不检查额度，不扣费，无需认证。使用 visitor 角色跳过所有余额验证。

Q4: userId 必须是真实用户吗？

A: 不需要。userId 可以是任意数字，仅用于区分不同用户的会话。建议使用您自己系统中的用户ID。

Q5: 一个对话组可以保存多少轮对话？

A: 对话组可以保存无限轮对话，但系统在构建上下文时默认只加载最近 12 轮对话，这样可以保证响应速度和上下文质量。

📌 总结

核心流程

  1. 创建对话组 → 获得 groupId
  2. 首次对话 → 传递 groupId，系统自动管理上下文
  3. 继续对话 → 继续传递相同的 groupId，系统自动加载历史
  4. 查询历史 → 使用 groupId 查询
  5. 删除对话 → 清理不需要的对话组

关键要点

✅ 所有接口无需认证
✅ 不检查额度，不扣费
✅ userId 可以是任意数字
✅ 只需使用 groupId 即可自动保持上下文
✅ 系统自动查询历史对话（默认最近12轮）
✅ 支持流式响应
✅ 支持语音、图片、文件
✅ 返回的 chatId 是对话记录ID

与旧方式的区别

对比项 ❌ 旧方式（不推荐） ✅ 新方式（推荐）
上下文管理 需要手动管理 parentMessageId 系统自动管理，只需 groupId
历史查询 需要手动传递消息链 系统自动查询最近12轮
代码复杂度 需要保存和更新多个ID 只需保存一个 groupId
容错性 ID丢失会断上下文 基于数据库，更可靠
