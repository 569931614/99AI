# 语音通话功能修复文档

## 修复日期
2025-10-01

## 问题总结

语音通话功能存在以下核心问题：

### 1. 延迟问题
- **问题**：后端需要累积 30 块音频（约 2.5 秒）才触发处理
- **影响**：用户说话后需要等待 2.5+ 秒才能得到响应
- **修复**：降低触发阈值到 15 块（约 1.3 秒），并添加超时强制处理机制

### 2. WebSocket 连接不稳定
- **问题**：开发环境硬编码端口，没有连接超时和错误恢复
- **影响**：连接失败无提示，用户体验差
- **修复**：
  - 智能检测环境（本地开发/HTTP/HTTPS）
  - 添加 10 秒连接超时
  - 改进错误提示和异常处理

### 3. 音频质量检查过严
- **问题**：振幅阈值 < 30 过滤掉很多正常语音
- **影响**：低音量说话无法识别
- **修复**：放宽到仅过滤完全静音（< 5）的音频

### 4. ASR 调用无重试
- **问题**：ASR 服务偶尔失败时直接返回错误
- **影响**：偶发性识别失败
- **修复**：添加最多 2 次重试机制，每次重试间隔递增

### 5. VAD（语音活动检测）过滤过严
- **问题**：前端 rms < 5 时不发送音频
- **影响**：轻声说话或环境噪音较小时丢失音频
- **修复**：降低阈值到 rms < 3，只过滤完全静音

## 测试步骤

### 前置条件
1. 确保阿里云 DashScope API Key 已配置
   - 在 `service/.env` 中设置 `DASHSCOPE_API_KEY`
   - 或在系统配置中设置 `dashscopeApiKey`

2. 确保 MySQL 和 Redis 正常运行

3. 启动服务：
   ```bash
   cd service
   pnpm dev  # 或 pnpm start
   ```

4. 启动前端：
   ```bash
   cd chat
   pnpm dev
   ```

#### 测试 1：基本连接测试
1. 打开聊天界面
2. 点击语音通话按钮

4. 查看日志面板是否显示 "WS 已连接"

**预期结果**：

1. 点击"按住说话"按钮

4. 观察日志和响应

**预期结果**：
- ASR 识别在 1.5 秒内开始
- LLM 响应流式返回
- TTS 语音播放（如果配置了音色）
- 总延迟 < 3 秒

#### 测试 3：连续通话测试
1. 点击"连续通话"按钮
2. 连续说话多句，中间停顿 1-2 秒
3. 再次点击停止

**预期结果**：
- 每句话在说完 1.3 秒后自动识别
- 不需要手动点击按钮
- 多轮对话正常

#### 测试 4：低音量测试
1. 降低说话音量（轻声）
2. 按住说话："测试低音量识别"
3. 松开按钮

**预期结果**：
- 即使音量较低，仍能正常识别
- 日志显示音频振幅 > 5

#### 测试 5：连接中断恢复测试
1. 开始录音
2. 停止后端服务（模拟断开）

**预期结果**：
- 前端显示"连接已断开"提示
- 录音自动停止
- 重启服务后可以重新连接

#### 测试 6：诊断功能测试

2. 点击"诊断"按钮
3. 查看日志输出

**预期结果**：

## 故障排查

### 问题 1：连接超时
**症状**：状态显示"连接超时，请检查网络或服务器状态"

**排查步骤**：
1. 检查后端服务是否启动：`curl http://localhost:9520/api/test/simple`
2. 检查 WebSocket 端口是否开放
3. 查看后端日志是否有错误

**解决方案**：
- 确保 `service/src/main.ts` 中的 WebSocket 服务已启动
- 检查防火墙设置

### 问题 2：ASR 识别失败
**症状**：日志显示 "[ERROR] asr: 语音识别失败"

**排查步骤**：
1. 检查 DashScope API Key 是否配置
2. 检查网络是否能访问阿里云服务
3. 查看后端详细日志

**解决方案**：
```bash
# 在 service/.env 中配置
DASHSCOPE_API_KEY=sk-xxxxx
```

### 问题 3：音频无声或识别不到
**症状**：说话后日志显示"音频几乎无声"

**排查步骤**：
1. 检查麦克风权限
2. 在浏览器设置中测试麦克风
3. 点击"诊断"查看 RMS 振幅

**解决方案**：
- 确保浏览器已授权麦克风权限
- 检查系统麦克风音量设置
- 尝试更换麦克风

### 问题 4：TTS 播放失败
**症状**：LLM 响应正常，但没有语音播放

**排查步骤**：
1. 检查是否配置了音色 ID
2. 查看日志是否有 TTS 错误
3. 检查浏览器控制台错误

**解决方案**：
- 在语音通话界面输入有效的音色 ID
- 或使用系统配置的默认音色
- 检查音色状态是否为 "SUCCESS"

## 后续优化建议

### 短期优化（1-2 周）
1. **使用 AudioWorklet 替代 ScriptProcessorNode**
   - ScriptProcessorNode 已废弃
   - AudioWorklet 性能更好，延迟更低

2. **添加自动重连机制**
   - 连接断开时自动尝试重连
   - 重连次数限制和指数退避

3. **改进 TTS 播放**
   - 使用 Web Audio API 的 SourceBuffer
   - 实现真正的流式播放（边收边播）

### 中期优化（1-2 月）
1. **集成专业 WebRTC 方案**
   - 参考 chat-realtime-vl 使用 LiveKit
   - 内置回声消除、降噪、自动增益

2. **实现真正的全双工通信**
   - 支持打断（interrupt）
   - 边说边回复

3. **添加情绪识别**
   - 根据语音情绪调整回复风格
   - 情绪化语音合成

### 长期优化（3+ 月）
1. **多模态支持**
   - 视频通话（参考 chat-realtime-vl）
   - 屏幕共享、白板

2. **离线模式**
   - 本地 ASR 模型（Whisper）
   - 本地 LLM（Ollama）
   - 离线 TTS

3. **高级功能**
   - 多人语音通话
   - 会议转录
   - 实时翻译
