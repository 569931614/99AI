🎙️ WebSocket 实时语音通话

实时双向语音对话，支持 ASR（语音识别）→ LLM（智能对话）→ TTS（语音合成）全链路，支持 VAD 自动检测说话结束、随时打断、情绪识别与音色切换。

连接信息

属性值
端点地址ws://your-domain/api/realtime/voice-call
协议WebSocket（支持文本和二进制消息）
鉴权暂无（开放接口）

客户端发送消息类型

1. start_call - 开始通话

消息类型：JSON 文本消息
字段说明必填
type固定值：'start_call'是
sampleRate采样率，推荐：8000 或 16000是
format音频格式：'pcm' 或 'wav'是
userId用户 ID是
appId角色应用 ID是
voiceId指定音色 ID（不填则使用角色默认音色）否
groupId会话组 ID（用于上下文关联）否
enableEmotion是否启用情绪检测（默认 true）否
enableAffection是否启用好感度系统（默认 true）否
响应：{ type: 'call_started', sampleRate: 8000, format: 'pcm' }

2. 音频数据 - 发送录音

消息类型：二进制消息（ArrayBuffer）
属性说明
格式PCM 16-bit 或 WAV 格式
采样率与 start_call 中指定的 sampleRate 一致
声道单声道（推荐）
发送方式实时流式发送，每次发送一小块音频数据
响应：实时返回 { type: 'asr.partial', text: '识别的部分文字' }

3. stop - 停止录音并触发处理

消息类型：JSON 文本消息
字段说明必填
type固定值：'stop'是
作用：停止当前录音，触发 ASR 最终识别 → LLM 生成回复 → TTS 语音播报
响应序列：asr.final → llm.start → llm.partial (多次) → llm.final → emotion.detected (可选) → tts.start → 音频数据 → tts.end → done

4. cancel - 取消当前播放

消息类型：JSON 文本消息
字段说明必填
type固定值：'cancel'是
作用：立即停止当前 TTS 播放（用于打断）
响应：{ type: 'canceled' }

5. end_call - 结束通话

消息类型：JSON 文本消息
字段说明必填
type固定值：'end_call'是
作用：正常结束通话，释放资源。建议在发送此消息后关闭 WebSocket 连接。

6. probe - 请求诊断信息

消息类型：JSON 文本消息
字段说明必填
type固定值：'probe'是
作用：获取服务端状态信息（用于调试）
响应：{ type: 'probe.resp', recvBytesTotal, recvChunkCount, bufferedChunks, isProcessing, ttsActive, lastRms, currentStage }

服务端发送消息类型

消息类型说明关键字段
call_started通话已启动sampleRate, format
asr.partial实时语音识别（部分）text, begin, end
asr.final语音识别完成text（完整识别文本）
llm.startAI 开始回复无
llm.partialAI 流式回复（部分）text（文本片段）
llm.finalAI 回复完成text（完整回复文本）, usage（token统计）
emotion.detected检测到情绪emotion（情绪类型，如 'happy', 'sad'）
tts.start开始语音播报无
tts.infoTTS 格式信息format（'mp3'）, sample_rate（22050）
音频数据TTS 播报音频（二进制）ArrayBuffer（MP3 音频流）
tts.end语音播报结束无
done本轮对话完成无
canceled操作已取消无
error错误信息stage（错误阶段）, message（错误描述）
probe.resp诊断信息响应recvBytesTotal, recvChunkCount, bufferedChunks, isProcessing, ttsActive, lastRms, currentStage

完整对话流程示例

典型的一轮对话流程：
步骤方向消息说明
1客户端 → 服务端{ type: 'start_call', ... }建立连接并启动通话
2服务端 → 客户端{ type: 'call_started' }通话已就绪
3客户端 → 服务端音频数据（ArrayBuffer）流式发送录音数据
4服务端 → 客户端{ type: 'asr.partial', text: '你' }实时识别（部分）
5服务端 → 客户端{ type: 'asr.partial', text: '你好' }实时识别（部分）
6客户端 → 服务端{ type: 'stop' }停止录音，触发处理
7服务端 → 客户端{ type: 'asr.final', text: '你好' }识别完成
8服务端 → 客户端{ type: 'llm.start' }AI 开始生成回复
9服务端 → 客户端{ type: 'llm.partial', text: '你' }流式回复（部分）
10服务端 → 客户端{ type: 'llm.partial', text: '好呀' }流式回复（部分）
11服务端 → 客户端{ type: 'llm.final', text: '你好呀，很高兴见到你！' }回复完成
12服务端 → 客户端{ type: 'emotion.detected', emotion: 'happy' }检测到情绪
13服务端 → 客户端{ type: 'tts.start' }开始语音合成
14服务端 → 客户端{ type: 'tts.info', format: 'mp3', sample_rate: 22050 }TTS 格式信息
15服务端 → 客户端音频数据（ArrayBuffer）MP3 音频流（可能多次）
16服务端 → 客户端{ type: 'tts.end' }语音播报结束
17服务端 → 客户端{ type: 'done' }本轮对话完成

音频格式要求

方向格式采样率比特率声道
客户端 → 服务端（录音）PCM 16-bit / WAV8000Hz（推荐）或 16000Hz-单声道（推荐）
服务端 → 客户端（TTS）MP322050Hz128kbps单声道

错误处理

错误阶段说明常见原因
asr语音识别失败音频格式不支持、音频质量差、无有效语音内容
llmAI 对话生成失败API 配额不足、网络超时、内容违规
tts语音合成失败音色 ID 无效、TTS 服务异常、文本过长

💡 与 WebSocket 语音通话的区别：
• HTTP 语音对话：一次性请求，等待完整结果返回（ASR+LLM+TTS 全部完成后才返回）
• WebSocket 语音通话：实时流式通信，支持边说边识别、打断、VAD 自动检测（推荐用于实时对话场景）

字段说明必填
userId外部用户ID是
prompt要合成的文本（支持括号内心理描述，如：你好啊~（开心地打招呼））是

chatId聊天记录ID（若未传appId则从此获取）否

voice音色类型，如：alloy、nova否

model语音模型（默认tts-1）否
功能特性：
1️⃣ 自动提取括号内心理描述用于情绪识别
2️⃣ 朗读时移除括号内容，只朗读实际文本
3️⃣ 音色选择优先级：指定emotion → AI识别情绪 → 角色情绪映射 → 角色默认音色 → 系统默认TTS
